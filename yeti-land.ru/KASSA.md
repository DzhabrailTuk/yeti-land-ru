# Касса: что уже готово и что осталось сделать

Сайт полностью готов к приёму оплаты. Сейчас касса выключена
(`js/config.js` → `kassa.provider: "off"`): заказ оформляется, пароль для
кассы выдаётся, деньги не списываются — гость платит на точке.

Чтобы включить настоящую оплату, нужна серверная половина. Её нельзя сделать
в браузере: секретный ключ кассы, который лежит в коде страницы, за пять
минут найдёт любой желающий и начнёт выписывать чеки от вашего имени.

---

## 1. Что нужно получить

| Что | Где | Зачем |
| --- | --- | --- |
| Договор с кассой | ЮKassa, Т-Касса, АТОЛ Онлайн | приём денег |
| Онлайн-касса (ФН) | у того же оператора или ОФД | чек по 54-ФЗ |
| `shopId` + секретный ключ | личный кабинет кассы | подпись запросов |
| Место под скрипты | хостинг сайта (PHP/Node) | два адреса ниже |

СБП и карты — это не две разные кассы, а два способа оплаты внутри одной.
На сайте гость уже выбирает между ними, выбор уходит в поле `method`.

---

## 2. Что нужно написать на хостинге

Два адреса. Их пути настраиваются в `js/config.js` → `kassa`.

### `POST /api/pay/create` — создать платёж

Принимает JSON от сайта:

```json
{
  "provider": "yookassa",
  "orderId": "YM4K2P1",
  "amount": { "value": "1010.00", "currency": "RUB" },
  "method": "sbp",
  "returnUrl": "https://yeti-land.ru/?paid=YM4K2P1",
  "description": "YETI · МАНГО 42 · Молодогвардейская",
  "cart": [{ "id": 60, "vol": "500", "qty": 2, "extras": ["tapioca"] }],
  "pickup": { "pointId": 1, "point": "…", "address": "…", "time": "~14:20", "code": "МАНГО 42" },
  "guest": { "name": "Тимур", "phone": "79968840808", "email": "guest@mail.ru" },
  "comment": "поменьше льда",
  "receipt": { "customer": { … }, "items": [ … ] }
}
```

Что делает:

1. **Считает сумму заново** по `cart` и своей копии `data/menu.js`. Всё, что
   пришло из браузера, гость может подделать — `amount` в запросе только для
   сверки. Не сошлось — отказ.
2. Создаёт платёж в кассе (свой `shopId` + секретный ключ) с чеком из
   `receipt` и адресом возврата `returnUrl`.
3. Сохраняет заказ у себя со статусом «ждёт оплаты».
4. Отвечает сайту:

```json
{ "id": "2f8c…", "url": "https://yoomoney.ru/checkout/…" }
```

Сайт уводит гостя по `url` на страницу банка.

### `GET /api/pay/status?id=…` — оплата прошла?

Отвечает `{ "paid": true }` или `{ "paid": false }` — по своей базе, а не по
тому, что сказал браузер. Сайт спрашивает это после возврата гостя: адрес
`?paid=…` гость может открыть и руками, поэтому одному возврату веры нет.

Если оставить `statusUrl` пустым, проверки не будет и сайт поверит возврату
из банка. Так можно только на время отладки.

### Вебхук кассы

Настраивается в личном кабинете кассы, сайт про него не знает. Касса сама
дёргает ваш адрес, когда деньги действительно пришли, — по нему и надо
переводить заказ в «оплачен» и отправлять его на точку. Подпись запроса
проверять обязательно.

---

## 3. Включить

В `js/config.js`:

```js
kassa: {
  provider: "yookassa",              // было "off"
  createUrl: "/api/pay/create",
  statusUrl: "/api/pay/status",
  returnUrl: "",                     // пусто — вернётся на эту же страницу
  vat: 1,                            // 1 — без НДС (УСН)
  currency: "RUB",
}
```

Всё. Кнопка «оплатить» сама начнёт уводить на страницу банка, а подпись под
ней сменится с «касса подключается — заказ примем без списания» на «оплата
пройдёт на защищённой странице банка».

---

## 4. Чек по 54-ФЗ

Позиции чека собирает `js/pay.js` → `receipt()`: строка корзины = позиция,
цена за штуку, допы дописываются в название.

- `vat_code` — ставка НДС из настроек: `1` без НДС (УСН), `2` — 0 %,
  `3` — 10 %, `4` — 20 %.
- `payment_subject: "commodity"` — товар.
- `payment_mode: "full_payment"` — полный расчёт.
- Почта гостя уже спрашивается на оформлении и уходит в `receipt.customer`.

Проверьте ставку НДС со своим бухгалтером до первого боевого платежа: с
неверной ставкой чеки уйдут в налоговую неправильными.

---

## 5. Что проверить перед запуском

- [ ] Тестовый магазин кассы: оплата проходит, чек приходит на почту.
- [ ] Сумма на странице банка совпадает с суммой в корзине.
- [ ] Гость закрыл страницу банка, не заплатив → вернулся, корзина цела.
- [ ] Оплата не прошла → показывается «оплата не прошла — попробуй ещё раз».
- [ ] Заказ виден на точке до того, как гость назовёт пароль.
- [ ] Оферта и политика обработки персональных данных лежат на сайте
      отдельными страницами (галочка на оформлении на них ссылается).
